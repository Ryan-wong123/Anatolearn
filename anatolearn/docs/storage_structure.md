# Teaching Content Storage

Updated 22 October 2026. Local file storage is separate from PostgreSQL metadata.

## Root and ownership

`backend/src/storage.js` configures PUBLIC_DIR (Docker: `/public`, mounted from `anatolearn/public`; non-Docker default: `backend/public`). It resolves teaching paths inside that root, validates model/material uploads and identifies local glTF companion references. Multer/fs writes and Express delivery still use local disk; cloud object storage requires a future adapter.

| Directory | Contents | Upload limit |
|---|---|---|
| models/anatomy | GLB, embedded glTF, OBJ, USDZ | 200 MiB |
| videos | MP4/WebM | 200 MiB |
| resources | PDF, DOC/DOCX, PNG/JPEG/WebP | 50 MiB |
| thumbnails | model-ID.png generated by teacher viewer | 10 MB JSON request limit |

Model/video/material uploads use UUID filenames with the original extension. Thumbnails intentionally use the model ID so a later capture replaces that model's thumbnail. Failed uploads remove their newly written files. Successful content deletion generally removes database records rather than automatically deleting older stored files.

## Delivery and permissions

All teaching-file routes require a verified bearer token or HttpOnly media-session cookie, plus an accessible owning content record. Students need publication and their account programme or shared content; teachers can preview drafts. Legacy glTF buffers/textures must be referenced by an accessible model. There is no unauthenticated express.static fallback. Asset responses use private/no-store and nosniff; native media byte ranges remain supported.

Vite public serving/copying is disabled. Its development fs deny rules block `/public`, `/@fs` aliases into teaching storage, backend sources and compose configuration. Production must route `/api`, `/models`, file paths under `/videos`, `/resources` and `/thumbnails` to the authenticated backend. Do not configure an independent static/CDN alias to PUBLIC_DIR. `/videos` and numeric video detail paths remain SPA routes.

Model attachment downloads additionally require is_downloadable=true for both roles; the default is false and teachers control it. This prevents the application's download action, not extraction of bytes already delivered for authorised WebGL viewing. No DRM or absolute copy prevention is claimed.

## Format handling

GLB headers/version/length, glTF version/embedded dependencies, OBJ vertices/faces and USDZ container signatures are checked. New standalone glTF uploads must embed buffers/images; use GLB for complete models that originally have companion files. Existing local glTF dependencies can be resolved through the owning model. Resource extensions and basic signatures must agree with the selected type; photo uploads accept PNG/JPEG/WebP. Reference URLs must use HTTP(S).

Original model downloads preserve the uploaded file. Annotation exports are separate JSON/CSV and are not embedded back into model files. See [3d_model_tools.md](3d_model_tools.md) for loader constraints.

## Operations

Migration 008 adds download permissions, image material types, quiz sessions/bank/timers and favourite-deletion triggers. Existing volumes require explicit additive migration; no volume reset is needed. Metadata and files must both be included in any backup. Automated backup/restore, retention of closed quiz sessions, orphan-file cleanup and cloud delivery remain operational work; never delete files solely because one metadata record was removed when another may reference the same path.
